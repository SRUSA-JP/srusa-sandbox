---
description: 検査を通してから変更を論理単位に分けてコミットする
---

現在の変更を CLAUDE.md のコミット規則に従ってコミットして。

1. まず `/check` の検査をすべて実行し、通ることを確認する。
   いずれかが失敗したらコミットせず、失敗内容を報告して止める。
2. `git status` と `git diff` で未コミットの変更をすべて確認する。
   秘密情報、`dist/`、`node_modules/`、`.claude/settings.local.json` が
   混ざっていないか確認する。
3. 変更を**論理単位**にグループ分けする（例: トークンの変更 / 画面の実装 /
   データの更新 / ドキュメント / ビルド設定）。まとめて 1 コミットにしない。
4. グループごとに、対象ファイルを明示して `git add <files>` → `git commit` する。
   `git add -A` や `git add .` は使わない。
5. コミットメッセージは `[prefix]要約` 形式（`[add]` / `[update]` / `[remove]` / `[clean]`）。
   プレフィックスと要約の間にスペースを入れない。要約は日本語。
   **何を変えたかより「なぜ変えたか」**を書く。
6. 最後に `git log --oneline` で分割結果を報告する。

このコマンドを実行したこと自体がコミットの許可とみなす（追加確認は不要）。
ただし push は含めない。`git push` / `git checkout` / `git reset` などの
非可逆的な操作は、別途明示の指示があるまで行わない。
